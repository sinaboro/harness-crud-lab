# 용어 풀이

처음 나오는 교시를 함께 적었다. 낱말이 기억나지 않으면 그 교시로 돌아가 본다.

## AI 와 하네스

| 용어 | 뜻 | 교시 |
|---|---|---|
| AI 모델 | 글을 받아 글을 돌려주는 프로그램. 파일을 보거나 명령을 실행하지 못한다. | 1 |
| AI 에이전트 | 모델의 지시에 따라 파일을 읽고 고치고 명령을 실행하는 프로그램. 이 과정에서는 OpenCode. | 1 |
| 하네스(harness) | 에이전트가 어떤 규칙으로, 어떤 도구를, 어디까지 써서 일하고, 무엇을 통과해야 끝나는지 정해 둔 장치 전체. 원래 뜻은 말에게 씌우는 마구. | 1 |
| 하네스 엔지니어링 | AI 가 일하는 환경(규칙·도구·권한·실행·검증)을 설계하는 일. | 1 |
| 바이브 코딩 | AI 에게 말로 시키고, 돌아가는 것 같으면 코드를 읽지 않고 받아들이는 방식. | 1 |
| 규칙 | AI 에게 하는 부탁. `AGENTS.md` 에 적는다. | 1, 5 |
| 권한 | AI 가 할 수 있는 일의 범위를 정한 잠금장치. `opencode.jsonc` 의 `permissions`. | 1, 5 |
| allow / ask / deny | 권한의 세 가지 처리. 그냥 허용 / 사람에게 물어봄 / 금지. | 5 |
| 검증 | 결과가 기준을 만족하는지 확인하는 일. 이 과정에서는 `scripts/verify.sh`. | 3, 5 |
| 요구사항 명세 | 무엇을 만들지를 "이렇게 부르면 → 이런 결과"로 적은 문서. `harness/REQUIREMENTS.md`. | 1, 4 |
| 작업 지시서 | AI 에게 일을 시킬 때 건네는 문서. 목표·요구사항·범위·하지 말 것·완료 조건·진행 방법. | 6 |
| 범위 | 이번 작업에서 고쳐도 되는 파일과 고치면 안 되는 파일. | 6 |
| 완료 조건 | "다 됐다"고 말할 수 있는 조건. 확인할 수 있는 문장으로 쓴다. | 6 |
| OpenRouter | 여러 회사의 AI 모델을 주소 하나, 키 하나로 부르게 해 주는 중개 서비스. | 2 |
| OpenCode | 이 과정에서 쓰는 AI 에이전트. 터미널에서 실행한다. | 2 |
| API 키 | "이 요청은 내 계정의 것"임을 증명하는 긴 문자열. 비밀번호처럼 다룬다. | 2 |
| 토큰 | AI 가 글을 세는 단위. 요금은 토큰 수로 계산한다. | 2 |
| 프롬프트 | AI 에게 보내는 글(질문이나 지시). | 2 |

## Docker

| 용어 | 뜻 | 교시 |
|---|---|---|
| Docker | 프로그램과 실행 환경을 상자(컨테이너)에 담아 실행하는 도구. | 2 |
| 이미지 | 프로그램과 실행 환경을 담아 둔 틀. 바뀌지 않는다. | 2 |
| 컨테이너 | 이미지로 만들어 실제로 돌아가는 것. 지우고 다시 만들 수 있다. | 2 |
| Dockerfile | 이미지를 만드는 순서를 적은 파일. | 2 |
| docker compose | 컨테이너 여러 개를 한꺼번에 켜고 끄는 도구. 설정은 `docker-compose.yml`. | 2 |
| 서비스 | `docker-compose.yml` 에 적은 컨테이너 하나의 이름(`db`, `app`, `dev`). 컨테이너끼리는 이 이름으로 서로를 부른다. | 2, 4 |
| 바인드 마운트 | 내 PC 의 폴더를 컨테이너 안의 폴더에 그대로 연결하는 것. 복사가 아니라 같은 폴더를 함께 본다. | 2 |
| 포트 | 한 컴퓨터 안에서 프로그램을 구분하는 번호. `8000:8000` 은 내 PC 의 8000 번을 컨테이너의 8000 번에 연결한다. | 2 |
| 환경 변수 | 프로그램 밖에서 넣어 주는 설정 값. 접속 주소나 키를 코드에 적지 않으려고 쓴다. | 2, 8 |
| `.env` | 환경 변수를 적어 두는 파일. Git 에 올리지 않는다. | 2 |

## 파이썬과 FastAPI

| 용어 | 뜻 | 교시 |
|---|---|---|
| 변수 | 값에 붙인 이름. | 3 |
| 문자열(str) | 따옴표로 감싼 글자. | 3 |
| 딕셔너리(dict) | `{"이름": 값}` 모양의 묶음. | 3 |
| 리스트(list) | `[값, 값]` 모양의, 순서가 있는 묶음. | 3 |
| 함수 | 이름을 붙인 일 묶음. `def` 로 만든다. | 3 |
| 인자 | 함수에 넘겨주는 값. | 3 |
| import | 다른 파일이나 패키지의 기능을 가져오는 것. | 3 |
| 데코레이터 | 함수 위에 `@` 로 붙이는 이름표. `@app.get("/hello")`. | 3 |
| FastAPI | 파이썬으로 웹 API 를 만드는 프레임워크. | 3 |
| uvicorn | FastAPI 앱을 실제로 실행해 주는 서버 프로그램. | 3 |
| 쿼리 파라미터 | 주소 뒤에 `?이름=값` 으로 붙이는 값. | 3 |
| 경로 파라미터 | 주소 안의 `{memo_id}` 자리에 들어가는 값. `/memos/7` 의 `7`. | 6 |
| Pydantic | 데이터의 모양을 클래스로 정하고 검사해 주는 패키지. | 4, 6 |
| `Field` | 항목의 규칙(최소·최대 길이, 기본값)을 적는 방법. | 6 |
| `response_model` | 응답의 모양을 정하는 설정. | 6 |
| `HTTPException` | 오류 응답(404 등)을 보내려고 일으키는 것. | 6 |
| `raise` | 함수를 그 자리에서 끝내고 오류를 알린다. | 6 |
| `/docs` | FastAPI 가 코드를 읽고 자동으로 만들어 주는 설명서 겸 시험 화면. | 3 |

## HTTP

| 용어 | 뜻 | 교시 |
|---|---|---|
| CRUD | Create(만들기)·Read(읽기)·Update(고치기)·Delete(지우기). | 1, 4 |
| API | 프로그램끼리 정해진 방식으로 주고받는 창구. | 3 |
| HTTP | 브라우저와 서버가 주고받는 말의 규칙. | 4 |
| 요청 / 응답 | 클라이언트가 보내는 것 / 서버가 돌려주는 것. | 4 |
| 방식(메서드) | 무엇을 하려는지. GET(보기)·POST(만들기)·PUT(고치기)·DELETE(지우기). | 4 |
| 본문(body) | 요청이나 응답에 실어 보내는 데이터. | 4 |
| 상태 코드 | 결과를 알리는 세 자리 숫자. 200·201·204·404·422·500. | 4 |
| JSON | 데이터를 글자로 적는 형식. `{"title": "장보기"}`. | 4 |
| curl | 명령 한 줄로 HTTP 요청을 보내는 도구. | 4 |
| 클라이언트 | 요청을 보내는 쪽(브라우저, curl, 테스트). | 4 |

## 데이터베이스

| 용어 | 뜻 | 교시 |
|---|---|---|
| 데이터베이스(DB) | 데이터를 디스크에 저장하고 안전하게 읽고 쓰게 해 주는 프로그램. 또는 그 안의 테이블 묶음. | 7 |
| PostgreSQL | 널리 쓰이는 무료 데이터베이스. | 7 |
| 테이블 / 행 / 열 | 표 / 데이터 한 건 / 항목. | 7 |
| SQL | 데이터베이스에게 일을 시키는 말. | 7 |
| psql | PostgreSQL 에 접속해 SQL 을 치는 프로그램. | 7 |
| `SERIAL` | 1, 2, 3 … 자동으로 번호를 붙이는 타입. | 7 |
| `PRIMARY KEY` | 행을 구분하는 열. 겹치지 않는다. | 7 |
| `NOT NULL` | 비워 둘 수 없다는 규칙. | 7 |
| `DEFAULT` | 값을 안 넣었을 때 쓰는 기본값. | 7 |
| `WHERE` | 조건에 맞는 행만 고른다. UPDATE·DELETE 에 빠뜨리면 모든 행이 대상이 된다. | 7 |
| `RETURNING` | INSERT·UPDATE·DELETE 한 행을 바로 돌려받는다. | 7 |
| psycopg | 파이썬에서 PostgreSQL 에 접속하는 드라이버. | 8 |
| 연결(connection) | 프로그램과 DB 사이의 통로. 열고, 쓰고, 닫는다. | 8 |
| 자리표시자(`%s`) | SQL 문장에서 값이 들어갈 자리. 값은 따로 전달한다. | 8 |
| SQL 인젝션 | 사용자가 보낸 글이 SQL 명령의 일부로 실행되는 공격. 자리표시자로 막는다. | 7, 8 |
| ORM | SQL 을 파이썬 코드 뒤에 감춰 주는 도구. 이 과정에서는 쓰지 않는다. | 8 |
| 커밋(DB) | DB 에서 변경을 확정하는 것. Git 의 커밋과 이름만 같다. | 8 |

|---|---|---|

| TestClient | 서버를 띄우지 않고 API 를 불러 보는 가짜 브라우저. | 3 |

| 테스트 전용 DB | 테스트만 쓰는 데이터베이스(`memo_test`). 진짜 데이터를 지우지 않으려고 따로 둔다. | 8 |
| 빨강 / 초록 | 테스트 실패 / 통과. 버그를 고칠 때 빨강을 먼저 확인하고 초록으로 만든다. | 11 |

## Git

| 용어 | 뜻 | 교시 |
|---|---|---|
| Git | 파일의 변경 기록을 관리하는 도구. | 2, 3 |
| 저장소(repository) | Git 이 기록을 관리하는 폴더. | 2 |
| clone | 인터넷의 저장소를 내 PC 로 내려받는 것. | 2 |
| 커밋(commit) | 지금 상태를 기록으로 남기는 것. 게임의 저장 지점. | 3 |
| `git diff` | 무엇이 바뀌었는지 보여 준다. `+` 는 추가, `-` 는 삭제. | 3 |
| `git add` | 이번 커밋에 넣을 파일을 고른다. | 3 |
| `.gitignore` | Git 이 무시할 파일 목록. | 2 |
| 훅(hook) | 커밋 같은 일이 일어날 때 Git 이 자동으로 실행하는 스크립트. | 5 |
| pre-commit | 커밋 직전에 실행되는 훅. 실패하면 커밋이 취소된다. | 5 |
| GitHub | Git 저장소를 인터넷에 올려 두는 서비스. | 12 |
| push | 내 PC 의 커밋을 GitHub 로 보내는 것. | 12 |
| 원격 저장소(remote) | 인터넷에 있는 저장소. `origin` 은 그 별명이다. | 12 |
