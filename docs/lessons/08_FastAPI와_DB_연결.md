# 8교시. 메모를 데이터베이스에 저장하도록 바꾸기

| | |
|---|---|
| 시간 | 2시간 |
| 실습 결과 | 메모가 데이터베이스에 저장되어, 서버를 다시 켜도 남는다 |
| 시작 상태 | 6교시의 메모 초안이 커밋되어 있다 |

6교시 결과가 없으면 **[dev]** `sh scripts/checkpoint.sh 06` 으로 가져온다.

> 이번 교시에서도 코드를 직접 쓰지 않는다. AI 에게 **저장하는 곳만 바꾸라고** 지시하고, 겉으로 드러나는 결과가 그대로인지 확인한다.

## 수업의 흐름에서 이번 교시의 위치

```text
 ① 요구사항 작성 → ② AI 에게 지시 → ③ 하네스로 제어 → ④ 실행·테스트 → ⑤ 수정·재검증·저장
 └────────────── 이번 교시: 두 번째 바퀴. 이번에는 "속만 바꾸는" 작업이다 ──────────────┘
```

## 학습 목표

1. "겉은 그대로, 속만 바꾼다"(저장하는 곳 교체)가 무슨 뜻인지 설명한다.
2. **테스트를 한 글자도 바꾸지 않는다**는 조건으로 AI 에게 일을 시키고, 지켜졌는지 확인한다.
3. 서버를 다시 켜도 메모가 남는지 확인한다.
4. 테스트 전용 데이터베이스가 왜 필요한지 설명하고, 진짜 메모가 지워지지 않는 것을 확인한다.

## 1. 개념

### 겉과 속

6교시에 만든 API 는 메모를 서버의 기억 속에 넣는다. 이번 교시에는 메모를 **데이터베이스**에 넣게 바꾼다.

```text
 바꾸지 않는 것 (겉)                    바꾸는 것 (속)
 ──────────────────────                ──────────────────────
 주소        POST /memos                저장하는 곳   서버의 기억 → 데이터베이스
 요청 모양   {"title": …}               저장하는 방식  메모리 안에 넣기 → 데이터베이스에 적기
 응답 모양   {"id": …, "title": …}
 상태 코드   201, 200, 404, 422
```

API 를 쓰는 쪽(브라우저, `curl`, 테스트)에서 보면 **아무것도 달라지지 않는다.** 달라지는 것은 하나, 서버를 다시 켜도 메모가 남는다는 점이다.

### 테스트는 계약서다

6교시에 만든 테스트는 "이렇게 부르면 이런 답이 온다"만 확인한다. 메모가 서버의 기억에 있는지 데이터베이스에 있는지는 묻지 않는다. 그래서 **속을 바꿔도 테스트는 그대로 통과해야 한다.**

이번 교시의 가장 중요한 조건:

> **`tests/test_memos.py` 는 한 글자도 바꾸지 않는다.**

AI 가 테스트를 고쳐 버리면 경보기가 꺼진다. 그래서 테스트 파일을 범위 밖으로 묶어 둔다.

### 테스트 전용 데이터베이스

테스트는 시작할 때마다 메모를 모두 지운다. 진짜 메모가 든 곳에서 테스트를 돌리면 **테스트할 때마다 내 메모가 지워진다.** (1교시의 사례 4 가 이것이다.) 그래서 데이터베이스를 두 개로 나눈다.

| 데이터베이스 | 누가 쓰는가 | 이름 |
|---|---|---|
| 진짜 메모 | 서버 | `memo_db` |
| 테스트 전용 | 테스트 | `memo_test` |

두 주소는 `docker-compose.yml` 이 컨테이너에 넣어 준다. 주소를 코드에 직접 적지 않는다. 환경 변수 `DATABASE_URL`(서버용)과 `TEST_DATABASE_URL`(테스트용)에서 읽는다.

**(7) 테스트가 진짜 메모를 지우지 않는가**

테스트를 돌리기 전과 뒤에 메모 개수를 센다.

**[dev]**

```bash

pytest -q
curl -s http://app:8000/memos | grep -o '"id"' | wc -l
```

- 첫 숫자와 마지막 숫자가 **같아야 한다.** 테스트를 돌렸는데도 내 메모는 그대로다.
- 숫자가 `0` 이 되었다면 테스트가 진짜 메모가 있는 곳에서 돌고 있는 것이다. **심각한 문제다.** AI 에게 지시서 5번의 "테스트 전용 데이터베이스" 조건을 가리켜 고치게 한다.

**(8) 안전 시험 — 이상한 글자를 넣어 본다**

데이터베이스에 저장할 때 사용자가 쓴 글이 **명령으로 실행되면 안 된다.** 그것을 직접 확인한다. 아래 파일을 컨테이너의 임시 폴더(`/tmp`)에 만든다. 프로젝트 폴더가 아니므로 Git 에 올라가지 않는다.

**[dev]**

```bash
cat > /tmp/attack.json << 'EOF'
{"title": "x'); DELETE FROM memos; --", "content": "안전 시험"}
EOF
curl -s -X POST http://app:8000/memos -H "Content-Type: application/json" --data-binary @/tmp/attack.json
curl -s http://app:8000/memos | grep -o '"id"' | wc -l
```

확인할 것:

- [ ] 응답의 `title` 이 **입력한 글자 그대로**다. (`x'); DELETE FROM memos; --`)
- [ ] 마지막 명령의 숫자가 이 시험 전보다 **1 늘었다.** 메모가 지워지지 않았다.

확인이 끝나면 시험 메모를 지운다. `id` 는 응답에 나온 번호를 쓴다.

**[dev]**

```bash
curl -s -X DELETE http://app:8000/memos/3
rm /tmp/attack.json
```

(`3` 은 응답에 나온 `id` 로 바꿔 친다.)

> 이 시험이 실패하면 AI 가 쓴 저장 코드가 **사용자가 쓴 글을 명령의 일부로 이어 붙인** 것이다. 이것을 **SQL 인젝션** 이라고 한다. 이 시험이 통과하도록 AI 에게 고치게 한다.

## 하네스 관점 — 이번 교시에서 본 것

- **테스트는 계약서다.** 저장하는 곳을 통째로 바꿨는데 테스트 12개가 그대로 통과했다. 겉이 바뀌지 않았다는 증거다.
- **범위 제한이 경보기를 지킨다.** "테스트 파일을 고치지 않는다"는 조건을 `git diff --stat` 한 줄로 확인했다.
- **확인은 한 단계 더 깊이.** AI 의 보고 → 내 `verify.sh` → `curl` → 서버를 다시 켜기 → 데이터베이스 상자를 다시 켜기 → 진짜 메모 개수 세기 → 안전 시험. 말보다 더 직접적인 증거로 내려간다.

## 자주 만나는 오류

| 증상 | 원인과 해결 |
|---|---|
| 서버 로그에 데이터베이스 연결 실패(`Name or service not known`) | 컨테이너 밖에서 실행했거나 주소의 이름을 `localhost` 로 적었다. 컨테이너 안에서는 `db` 다. |
| `KeyError: 'DATABASE_URL'` 또는 `'TEST_DATABASE_URL'` | 환경 변수가 없다. dev 컨테이너 안에서 실행했는지 확인한다. **[PS]** `docker compose up -d` 뒤 다시 들어간다. |
| 서버는 켜졌는데 `[]` 만 나오고 메모 저장이 안 된다 | 데이터베이스 상자가 아직 준비되지 않았을 수 있다. **[PS]** `docker compose ps` 에서 `db` 가 `(healthy)` 인지 본다. |
| 서버가 500 을 돌려준다 | **[PS]** `docker compose logs app --tail 30` 에서 `Traceback` 의 마지막 줄을 읽는다. 그 출력을 AI 에게 붙여 준다. |
| 테스트를 돌리면 진짜 메모가 사라진다 | 테스트가 진짜 데이터베이스에서 돈다. 4단계 (7)의 방법으로 확인하고, AI 에게 지시서 5번을 가리켜 고치게 한다. |
| 시각이 9시간 어긋나 보인다 | 응답 끝의 `Z` 는 세계 표준시(UTC)다. 한국 시각은 9시간을 더한 값이다. 10교시에 화면에서 한국 시각으로 바꿔 보여 준다. |
