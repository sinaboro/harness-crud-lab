## 1. 개념 — 메모를 어디에 적어 둘까?

4교시에 서버를 다시 켜자 메모가 모두 사라졌다. 메모가 **서버 프로그램의 기억 속**에만 있었기 때문이다.

**데이터베이스(DB)** 는 메모를 **프로그램 밖의 공책 상자**에 적어 두는 프로그램이다. 서버가 꺼져도 공책은 남는다. 우리 과정에서는 **PostgreSQL** 이라는 데이터베이스를 쓴다.

| 낱말 | 쉬운 뜻 |
|---|---|
| 데이터베이스 | 데이터를 디스크에 적어 두고 꺼내 쓰는 프로그램 |
| 컨테이너 | 프로그램이 돌아가는 상자. 지우고 다시 만들 수 있다 |
| 데이터 폴더 | 상자 안의 데이터를 **내 PC 의 폴더**에 연결해 둔 곳 (2교시의 바인드 마운트) |

우리 PC 에서 데이터 폴더는 이 위치다.

```text
C:\harness-crud-lab\data\postgres\
```

이 폴더 안에는 PostgreSQL 이 쓰는 파일이 많이 있다. **직접 열거나 고치지 않는다.**

---

## 따라 하기

### 1단계. 데이터베이스 컨테이너 상태 보기 (5분)

**[PS]**

```powershell
cd C:\harness-crud-lab
docker compose ps
```

`db` 줄의 `STATUS` 칸에 `(healthy)` 가 있으면 데이터베이스가 일할 준비가 된 것이다.

### 2단계. 데이터 폴더의 파일 세기 (5분)

**[PS]**

```powershell
(Get-ChildItem C:\harness-crud-lab\data\postgres -Recurse -File).Count
```

출력된 숫자를 **종이에 적는다.** 3단계 뒤에 다시 셀 것이다.

### 3단계. 데이터베이스 컨테이너를 지우고 다시 만들기 (15분)

**[PS]** 컨테이너 세 개를 모두 내린다. 지우는 것은 **컨테이너**이고, 데이터 폴더는 지워지지 않는다.

```powershell
docker compose down
docker compose ps
```

`docker compose ps` 에 아무것도 나오지 않으면 정상이다.

**[PS]** 다시 켠다.

```powershell
docker compose up -d
docker compose ps
```

`db` 가 `(healthy)` 가 될 때까지 몇 십 초 기다린다.

**[PS]** 다시 센다.

```powershell
(Get-ChildItem C:\harness-crud-lab\data\postgres -Recurse -File).Count
```

2단계에서 적은 숫자와 **비슷한가?** 숫자가 0 이 아니고 많이 줄지 않았다면, 상자는 새로 만들었지만 데이터는 그대로 남은 것이다. 숫자가 몇 개 달라지는 것은 정상이다. 데이터베이스가 켜질 때 기록 파일을 조금 바꾸기 때문이다.

> 상자는 지워지고 다시 만들어졌다. 데이터는 `C:\harness-crud-lab\data\postgres` 폴더에 있었고, 새 상자가 그 폴더를 다시 연결해서 이어 쓴다. 이것이 2교시에 배운 **바인드 마운트**다.

**[PS]** 작업실에 다시 들어간다. 이제 dev 안에서 명령을 친다.

```powershell
docker compose exec dev bash
```

### 4단계. AI 에게 쉬운 말로 설명 듣기 (15분)

**[dev]**

```bash
python scripts/ask_ai.py "데이터베이스가 무엇인지, 프로그램이 꺼져도 데이터가 남는 이유가 무엇인지 초보자에게 세 문장으로 설명해 줘."
```

AI 의 답을 읽고, **내 말로 다시 세 문장** 적는다. 적지 못하는 부분이 있으면 다시 묻는다.

### 5단계. 8교시 준비 읽기 (10분)

8교시에 AI 에게 시킬 작업 지시서를 미리 읽는다. 코드를 이해할 필요는 없다. 아래 두 칸만 찾는다.

**[dev]**

```bash
cat harness/tasks/08_db_connect.md
```

- **1. 목표**: 무엇이 바뀌는가? (힌트: 저장하는 곳만 바뀐다)
- **4. 하지 말 것**: 무엇을 하지 않는가?

## 하네스 관점 — 이번 교시에서 본 것

- 데이터는 **실행 환경(컨테이너) 밖**에 둔다. 컨테이너는 언제든 지우고 다시 만들 수 있다. 데이터 폴더가 남아 있으면 실수로 상자를 지워도 기록은 지켜진다.
- 8교시에 AI 가 이 상자를 쓰는 코드를 쓴다. 그때도 우리가 확인하는 것은 **겉으로 보이는 결과**(주소, 응답, 테스트)다.

## 자주 만나는 오류

| 증상 | 원인과 해결 |
|---|---|
| `docker compose ps` 의 `db` 가 `starting` 에 오래 머문다 | 처음 켤 때는 몇 분 걸릴 수 있다. 기다린 뒤 다시 본다. 계속 그러면 [troubleshooting.md](../troubleshooting.md) 의 "DB 가 켜지지 않는다"를 본다. |
| `Get-ChildItem` 결과가 `0` 이다 | 데이터 폴더가 아직 만들어지지 않았을 수 있다. 1단계에서 `db` 가 `healthy` 인지 확인한다. |
| 데이터 폴더를 실수로 지웠다 | 메모가 모두 사라진다. 8교시 전이므로 괜찮다. 다시 `docker compose up -d` 로 빈 데이터베이스가 만들어진다. |

## 확인 문제

1. 4교시에서 서버를 다시 켜자 메모가 사라졌다. 메모가 있던 곳이 어디였기 때문인가?
2. `docker compose down` 은 무엇을 지우고, 무엇을 남기는가?
3. 데이터 폴더의 파일 수가 2단계와 3단계에서 같았다. 이것이 무엇을 뜻하는가?
