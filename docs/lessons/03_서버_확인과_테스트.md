# 3교시. 서버 확인하고 테스트하고 저장하기

| | |
|---|---|
| 시간 | 2시간 |
| 실습 결과 | `/hello` 주소를 확인하고, 테스트를 실행하고, 커밋한다 |
| 시작 상태 | 2교시를 마친 상태 (컨테이너 3개가 켜져 있다) |

> **이 과정은 파이썬, FastAPI, SQL 문법을 가르치지 않는다.**
> 필요한 코드는 완성 예시(`checkpoints/`)로 준다. 우리가 할 일은 **코드가 무엇을 하는지 확인하고, 테스트하고, 저장하는 것**이다.

## 수업의 흐름에서 이번 교시의 위치

```text
 ① 요구사항 작성 → ② AI 에게 지시 → ③ 하네스로 제어 → ④ 실행·테스트 → ⑤ 수정·재검증·저장
 └─ 이번 교시: 실행해서 확인하고, 테스트를 돌리고, 저장하는 일을 손으로 한 번 해 본다 ─┘
```

## 학습 목표

1. 주소(`/health`, `/hello`)에 요청을 보내고 응답을 읽는다.
2. `/docs` 화면에서 API 를 직접 눌러 본다.
3. 테스트를 실행하고, 일부러 실패시켜 본 뒤 되돌린다.
4. `git diff` 로 바뀐 것을 보고 커밋한다.

## 따라 하기

### 1단계. 3교시 완성 예시 가져오기 (5분)

**[dev]**

```bash
sh scripts/checkpoint.sh 03
```

```text
checkpoints/lesson03 의 app, tests 를 가져왔습니다.
```

이 명령은 `app` 폴더와 `tests` 폴더를 3교시 완성본으로 바꾼다. 2교시에는 이 폴더에 아무것도 저장하지 않았으므로 그대로 실행하면 된다.

**[dev]**

```bash
ls app tests
```

`app` 에 `main.py`, `tests` 에 `conftest.py`, `test_health.py` 가 보이면 된다.

### 2단계. 브라우저로 주소 확인하기 (10분)

서버는 컨테이너에서 이미 켜져 있다. 파일을 고치면 저절로 다시 켜지므로 서버를 따로 켤 필요는 없다.

브라우저에서 아래 주소를 차례로 연다.

| 주소 | 화면에 보이는 것 |
|---|---|
| http://localhost:8000/health | `{"status":"ok"}` |
| http://localhost:8000/hello | `{"message":"안녕하세요, 하네스!"}` |
| http://localhost:8000/hello?name=철수 | `{"message":"안녕하세요, 철수!"}` |
| http://localhost:8000/nothing | `{"detail":"Not Found"}` |

- 주소 뒤의 `?name=철수` 는 **"이름을 이 값으로 해 달라"는 쪽지**다. 응답의 `철수` 가 그 쪽지에서 왔다.
- 없는 주소를 부르면 서버가 "그런 주소는 없다"고 답한다.

### 3단계. `/docs` 에서 눌러 보기 (10분)

브라우저에서 http://localhost:8000/docs 를 연다.

1. `GET /hello` 를 누르고 **Try it out** 을 누른다.
2. `name` 칸에 자기 이름을 넣고 **Execute** 를 누른다.
3. 아래에 응답이, **Code** 칸에 `200` 이 나오면 성공이다.

`/docs` 는 서버가 자동으로 만든 설명서이자 시험 화면이다. 우리가 쓴 적이 없다.

### 4단계. AI 에게 설명 듣고, 직접 확인하기 (15분)

**[dev]**

```bash
python scripts/ask_ai.py --file app/main.py "이 파일에 주소가 몇 개 있고, 각 주소가 무엇을 돌려주는지 초보자에게 쉽게 알려 줘."
```

AI 의 답을 그대로 믿지 않는다. 답에 나온 주소를 **브라우저에서 직접 열어 확인한다.**

| AI 가 말한 것 | 브라우저에서 본 것 | 같은가? |
|---|---|---|
| (예: `/health` 는 상태를 돌려준다) | | |
| (예: `/hello` 는 이름을 받아 인사한다) | | |

이번에는 에이전트에게 같은 것을 시킨다. 에이전트는 파일 이름만 알려 줘도 스스로 파일을 읽는다.

**[dev]**

```bash
opencode run "app/main.py 를 읽고, /hello?name=철수 를 불렀을 때 무슨 일이 일어나는지 순서대로 설명해 줘. 파일은 고치지 마."
```

> "파일은 고치지 마"를 꼭 붙인다. 지금은 규칙과 권한이 없어서 말로 부탁하는 것 말고는 막을 방법이 없다. 5교시에 해결한다.

### 5단계. 테스트 실행하기 (15분)

**테스트**는 "이렇게 부르면 이런 답이 와야 한다"를 적어 둔 **자동 확인 목록**이다. 사람이 브라우저를 열어 확인하는 대신, 프로그램이 같은 확인을 매번 대신한다.

`tests/test_health.py` 에 세 가지 확인이 적혀 있다. 열어서 주소와 기대하는 답을 찾아본다. 코드를 읽지 않아도 된다.

**[dev]**

```bash
pytest -q
```

```text
...                                                                      [100%]
3 passed in 0.03s
```

점(`.`) 하나가 통과한 확인 하나다. 이제 코드 검사와 테스트를 한꺼번에 돌린다.

**[dev]**

```bash
sh scripts/verify.sh
```

마지막 줄이 `검증 통과: 이제 저장(commit)해도 됩니다.` 이면 된다.

### 6단계. 일부러 실패시켜 보기 (10분)

테스트는 **바뀐 것을 알려 주는 경보기**다. 실제로 울리는지 확인한다.

1. VS Code 에서 `app/main.py` 를 연다. **Ctrl+F** 를 누르고 `안녕하세요` 를 찾는다.
2. `안녕하세요` 를 `반갑습니다` 로 바꾸고 **Ctrl+S** 로 저장한다.
3. **[dev]** `pytest -q` 를 실행한다.

```text
FAILED tests/test_health.py::test_hello_default
FAILED tests/test_health.py::test_hello_with_name
2 failed, 1 passed
```

출력에서 세 가지를 찾는다.

- `FAILED` 로 시작하는 줄: 어떤 확인이 실패했는가
- 그 아래 `assert` 줄: **기대한 답**과 **실제 답**이 어떻게 다른가
- 마지막 줄: 몇 개가 실패했는가

확인했으면 `반갑습니다` 를 다시 `안녕하세요` 로 **되돌리고** 저장한 뒤, `pytest -q` 로 `3 passed` 를 확인한다.

### 7단계. 바뀐 것을 보고 저장하기 (10분)

**[dev]**

```bash
git status
git diff --stat
```

`git status` 에 `app/main.py` 와 `tests` 폴더의 파일이 보인다. `.env` 는 보이지 않아야 한다. 정상이다.

**[dev]**

```bash
git add -A
git commit -m "3교시: /hello 주소와 테스트 추가"
git log --oneline -1
```

맨 위에 방금 만든 커밋이 있으면 저장이 끝났다.

> 커밋은 "지금 상태를 기록으로 남기는 것"이다. 나중에 망가지면 이 지점으로 돌아올 수 있다.

## 하네스 관점 — 이번 교시에서 본 것

이번 교시에는 수업의 흐름 ④·⑤를 **사람이 손으로** 했다.

| 한 일 | 손으로 한 방법 | 5교시부터는 |
|---|---|---|
| 실행·확인 | 브라우저와 `/docs` 를 눈으로 봤다 | 테스트가 대신 확인한다 |
| 검증 | `sh scripts/verify.sh` 를 직접 쳤다 | 커밋할 때 자동으로 실행된다 |
| AI 통제 | "파일은 고치지 마"라고 말로 부탁했다 | 규칙과 권한이 대신한다 |
| 저장 | 검증을 건너뛰고도 커밋할 수 있다 | 검증에 실패하면 커밋이 취소된다 |

## 자주 만나는 오류

| 증상 | 원인과 해결 |
|---|---|
| 브라우저에 `{"detail":"Not Found"}` | 주소를 잘못 입력했다. 또는 파일을 저장하지 않았다. VS Code 탭에 흰 점이 있으면 저장되지 않은 것이다. |
| 브라우저가 "사이트에 연결할 수 없음" | 파일에 실수가 있어 서버가 켜지지 못했다. **[PS]** `docker compose logs app --tail 20` 에서 `Error` 가 있는 줄을 찾는다. 실수를 되돌리고 다시 저장한다. |
| `pytest: command not found` | 윈도우 PowerShell 에서 쳤다. pytest 는 컨테이너 안에만 있다. `docker compose exec dev bash` 로 들어가서 친다. |
| `git commit` 이 `Please tell me who you are` | 2교시 10단계(이름·메일 설정)를 하지 않았다. |
| 한글이 `안녕` 처럼 보인다 | 브라우저 확장이나 다른 도구에서 그렇게 보일 수 있다. `/docs` 의 Response body 로 확인한다. |

## 확인 문제

1. `/hello?name=영희` 를 브라우저에서 열면 응답에 무엇이 나오는가?
2. 파일을 고쳤는데 서버를 다시 켜지 않았다. 왜 바뀐 내용이 보이는가? (힌트: 2교시의 바인드 마운트)
3. 테스트가 실패했을 때 가장 먼저 어디를 읽는가?
4. `git commit` 전에 `git diff` 로 무엇을 확인하는가?
