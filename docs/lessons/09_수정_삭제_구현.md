## 1. 개념

### PUT 과 DELETE

| | PUT `/memos/1` | DELETE `/memos/1` |
|---|---|---|
| 뜻 | 1번 메모를 이 내용으로 바꿔라 | 1번 메모를 지워라 |
| 요청 본문 | 있다 (`{"title": …, "content": …}`) | 없다 |
| 성공 | **200** + 고쳐진 메모 | **204**, 본문 없음 |
| 번호가 없으면 | 404 | 404 |
| 입력이 틀리면 | 422 (R6) | — |

- PUT 은 메모 **전체**를 새 내용으로 바꾼다. 제목만 보내고 내용을 빼면 내용은 기본값(`""`)이 된다.
- DELETE 가 204 인 이유: 지워서 없어진 것을 돌려줄 수는 없다. "성공했고 돌려줄 것은 없다"가 204 다.

### 되돌릴 수 없는 작업

만들기와 보기는 잘못되어도 피해가 작다. 고치기와 지우기는 다르다. **있던 데이터가 바뀌거나 사라진다.** 7교시에 본 대로 `WHERE` 를 빠뜨리면 모든 메모가 한꺼번에 바뀌거나 지워진다.

그래서 이번 교시에는 검토할 것이 하나 더 있다. **AI 가 쓴 `UPDATE`·`DELETE` 문을 한 줄씩 직접 본다.**

### 5단계. ⑤ 코드 읽기 (25분)

완성 예시(`checkpoints/lesson09`)를 기준으로 읽는다.

**(1) 고치기**

```python
@app.put("/memos/{memo_id}", response_model=MemoOut)
def update_memo(memo_id: int, memo: MemoIn) -> dict:
    with get_conn() as conn:
        # WHERE 가 없으면 모든 메모가 바뀐다. 반드시 id 로 한 건만 고른다.
        row = conn.execute(
            "UPDATE memos SET title = %s, content = %s, updated_at = now() "
            "WHERE id = %s RETURNING *",
            (memo.title, memo.content, memo_id),
        ).fetchone()
    if row is None:
        raise not_found()
    return row
```

- 인자가 둘이다. `memo_id` 는 **주소**에서, `memo` 는 **본문**에서 온다. FastAPI 가 알아서 나눠 준다.
- `memo: MemoIn` — 만들기와 **같은 클래스**를 쓴다. 그래서 입력 규칙(R6)이 고치기에도 저절로 적용된다. 규칙을 한 곳에만 적어 두는 이유다.
- `%s` 가 세 개, 값도 세 개. **순서가 맞아야 한다.** `(memo.title, memo.content, memo_id)` 의 순서를 SQL 의 `%s` 순서와 하나씩 짚어 본다.
- 문자열 두 줄이 나란히 있으면 파이썬이 하나로 이어 붙인다. 첫 줄 끝의 공백(`now() "`)이 없으면 `now()WHERE` 가 되어 오류가 난다.
- 없는 번호면 `UPDATE` 는 0행을 바꾸고 `RETURNING` 은 아무것도 돌려주지 않는다. 그래서 `row` 가 `None` 이 되고 404 가 된다. 7교시 5·7단계에서 본 "DB 는 없다를 오류로 알리지 않는다"를 코드가 처리한 것이다.

**(2) 지우기**

```python
@app.delete("/memos/{memo_id}", status_code=204)
def delete_memo(memo_id: int) -> None:
    with get_conn() as conn:
        row = conn.execute(
            "DELETE FROM memos WHERE id = %s RETURNING id", (memo_id,)
        ).fetchone()
    if row is None:
        raise not_found()
    # 204 는 "성공했고, 돌려줄 내용은 없음"이라는 뜻이라 아무것도 돌려주지 않는다.
```

- `-> None` 과 `return` 없음 — 돌려줄 것이 없다. 204 와 짝이다.
- `RETURNING id` — 지운 행의 번호를 돌려받는다. 지운 것이 없으면 `None` 이다. 이것으로 "지웠는가, 없었는가"를 구분한다.

**(3) 404 를 한 곳으로**

```python
def not_found() -> HTTPException:
    """'그 번호의 메모가 없다'는 404 오류를 한 곳에서 만든다."""
    return HTTPException(status_code=404, detail="메모를 찾을 수 없습니다.")
```

보기·고치기·지우기 세 곳에서 같은 404 를 쓴다. 문구를 세 번 적으면 언젠가 한 곳만 다르게 고쳐지는 일이 생긴다. 한 곳에 두면 그럴 수 없다.

**(4) 테스트**

```python
def test_update_memo(client):
    created = make_memo(client)
    response = client.put(
        f"/memos/{created['id']}", json={"title": "장보기(수정)", "content": "우유"}
    )
    assert response.status_code == 200
    assert response.json()["title"] == "장보기(수정)"
    # 다시 조회해도 바뀐 내용이 남아 있어야 한다(진짜로 저장되었는지 확인).
```

마지막 줄에 주목한다. PUT 의 응답만 보지 않고 **다시 조회해서** 확인한다. 응답만 그럴듯하게 돌려주고 저장은 하지 않는 버그를 잡는다.

### 6단계. CRUD 한 장으로 정리하기 (10분)

| 하는 일 | HTTP | 파이썬 함수 | SQL | 성공 | 실패 |
|---|---|---|---|---|---|
| 만들기 | `POST /memos` | | `INSERT … RETURNING *` | 201 | 422 |
| 목록 | `GET /memos` | | `SELECT … ORDER BY id DESC` | 200 | — |
| 한 건 | `GET /memos/{id}` | | `SELECT … WHERE id = %s` | 200 | 404 |
| 고치기 | `PUT /memos/{id}` | | | 200 | 404, 422 |
| 지우기 | `DELETE /memos/{id}` | | | 204 | 404 |

## 하네스 관점 — 이번 교시에서 본 것

- **테스트 조건의 세 가지 모양.** 6교시 "만들어라", 8교시 "한 글자도 바꾸지 마라", 9교시 "늘리기만 해라". 작업의 성격에 따라 테스트를 묶는 방식이 달라진다. 그리고 매번 `git diff` 한 줄로 확인했다.
- **위험한 작업일수록 사람이 직접 본다.** 되돌릴 수 없는 `UPDATE`·`DELETE` 는 테스트 통과만 믿지 않고 SQL 세 줄을 눈으로 봤다.
- **테스트도 검증 대상이다.** 코드를 일부러 망가뜨려 테스트가 알아채는지 봤다. 못 알아챘다면 그 빈틈을 메우는 것이 하네스를 고치는 일이다.
- **지시서를 쓰는 것이 설계다.** 2단계에서 범위와 "하지 말 것"을 정할 때, 이미 무엇을 어떻게 만들지 절반은 결정했다.

## 자주 만나는 오류

| 증상 | 원인과 해결 |
|---|---|
| PUT 이 405 `Method Not Allowed` | `@app.put("/memos/{memo_id}")` 가 없거나 주소가 다르다. `/docs` 에서 PUT 이 보이는지 확인한다. |
| PUT 에 제목만 보냈더니 내용이 지워졌다 | 정상이다. PUT 은 전체를 바꾼다. 안 보낸 `content` 는 기본값 `""` 가 된다. |
| `syntax error at or near "WHERE"` | 두 줄로 나눈 SQL 문자열 사이에 공백이 없다(`now()WHERE`). 첫 줄 끝에 공백을 넣는다. |
| `the query has 3 placeholders but 2 parameters were passed` | `%s` 의 개수와 값의 개수가 다르다. 하나씩 짚어 센다. |
| 고쳤는데 다른 메모까지 바뀌었다 | `WHERE` 가 없다. 4단계 (3)의 검사를 한다. DB 의 데이터는 되돌릴 수 없으니 메모를 다시 만든다. |
| DELETE 가 200 과 `null` 을 돌려준다 | `status_code=204` 를 빠뜨렸다. 요구사항 R5 를 가리켜 고치게 한다. |
| `grep "^-"` 에 출력이 있다 | 기존 테스트의 줄이 지워졌거나 바뀌었다. `git diff tests/` 전체를 읽고, 이유를 AI 에게 묻는다. |
