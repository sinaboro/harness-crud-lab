# 9교시. 수정·삭제 구현

| | |
|---|---|

| 시작 상태 | 8교시를 마친 상태 (메모가 데이터베이스에 저장되고 커밋되어 있다) |

## 수업의 흐름에서 이번 교시의 위치

```text
 ① 요구사항 작성 → ② AI 에게 지시 → ③ 하네스로 제어 → ④ 실행·테스트 → ⑤ 수정·재검증·저장
 └────────────── 이번 교시: 세 번째 바퀴. 이번에는 내가 지시서를 먼저 써 본다 ──────────────┘
```

## 학습 목표

1. 작업 지시서를 직접 써 보고, 준비된 지시서와 비교한다.
2. 고치기(PUT)와 지우기(DELETE)의 요청·응답·상태 코드를 설명한다.
3. "테스트는 추가만, 기존 테스트는 금지"라는 조건을 `git diff` 로 확인한다.
4. 메모가 여러 건일 때 **한 건만 바뀌는지** 직접 확인한다.
5. CRUD 네 가지가 HTTP 로 어떻게 이어지는지 한 장의 표로 정리한다.

## 1. 개념

### PUT 과 DELETE

| | PUT `/memos/1` | DELETE `/memos/1` |
|---|---|---|
| 뜻 | 1번 메모를 이 내용으로 바꿔라 | 1번 메모를 지워라 |
| 요청 본문 | 있다 (`{"title": …, "content": …}`) | 없다 |
| 성공 | **200** + 고쳐진 메모 | **204**, 본문 없음 |
| 번호가 없으면 | 404 | 404 |
| 입력이 틀리면 | 422 (R6) | — |

- PUT 은 메모 **전체**를 새 내용으로 바꾼다. 제목만 보내고 내용을 빼면 내용은 빈 글자가 된다.
- DELETE 가 204 인 이유: 지워서 없어진 것을 돌려줄 수는 없다. "성공했고 돌려줄 것은 없다"가 204 다.

### 되돌릴 수 없는 작업

만들기와 보기는 잘못되어도 피해가 작다. 고치기와 지우기는 다르다. **있던 데이터가 바뀌거나 사라진다.** 그래서 이번 교시에는 확인할 것이 하나 더 있다. **다른 메모가 함께 바뀌거나 지워지지 않았는가.**

## 따라 하기

### 1단계. ① 요구사항 읽기 (5분)

`harness/REQUIREMENTS.md` 의 **R4, R5** 를 읽는다. 조건을 종이에 번호를 붙여 옮겨 적는다. 4단계에서 이 목록을 하나씩 확인한다.

### 2단계. ② 작업 지시서를 내가 먼저 쓰기 (20분)

지금까지는 준비된 지시서를 썼다. 이번에는 **보기 전에 먼저 써 본다.** 메모장에 아래 여섯 칸을 적는다(저장하지 않아도 된다).

| 칸 | 스스로 묻는다 |
|---|---|
| 1. 목표 | 이 작업이 끝나면 무엇이 되어 있는가? |
| 2. 요구사항 | 어느 번호인가? 고치기에도 입력 규칙이 적용되는가? |
| 3. 범위 | 어떤 파일을 고쳐야 하는가? 테스트 파일은 어떻게 다뤄야 하는가? (8교시에는 "고치지 않는다"였다. 이번에는?) |
| 4. 하지 말 것 | AI 가 덧붙일 만한 것은 무엇인가? (일부만 고치기, 휴지통, 화면 …) |
| 5. 완료 조건 | 테스트 개수는 어떻게 되어야 하는가? |
| 6. 진행 방법 | 계획 → 승인 → 구현 → 검증 → 보고 |

다 썼으면 `harness/tasks/09_update_delete.md` 를 열어 비교한다.

- 준비된 지시서에 있는데 내 것에 없는 조건은 무엇인가? 그 조건이 없으면 어떤 일이 생길 수 있는가?
- 3번 범위의 "테스트 **추가**만"과 6번의 "`git diff tests/` 에서 지워진 줄이 없다"를 찾는다. 8교시의 "한 글자도 바꾸지 않는다"가 이번에는 "**늘리기만 한다**"가 되었다.

이번 실습은 준비된 지시서로 진행한다. 내 지시서가 더 낫다고 생각되는 부분은 지시할 때 말로 덧붙인다.

### 4단계. ④ 검증 (25분)

다른 dev 셸에서 직접 확인한다. **[PS]** `docker compose exec dev bash`

**(1) 기계가 확인하는 것**

**[dev]**

```bash
sh scripts/verify.sh
```

- [ ] "검증 통과"로 끝난다.
- [ ] 테스트 개수가 3단계의 숫자보다 **늘었다.**

**(2) 기존 테스트가 그대로인가 — 이번 교시의 핵심 확인**

**[dev]**

```bash
git diff --stat
git diff tests/ | grep "^-" | grep -v "^---"
```

- [ ] 첫째 명령: `app/main.py` 와 `tests/test_memos.py` 두 파일만 나온다.
- [ ] 둘째 명령: **아무것도 출력되지 않는다.** (지워진 줄이 없다)

출력이 있으면 AI 가 기존 테스트를 건드린 것이다. 무엇을 왜 바꿨는지 묻고 되돌리게 한다.

**(3) 메모 두 건으로 직접 시험하기 — 다른 메모가 안 바뀌는가**

이번 교시에서 가장 중요한 시험이다. 메모가 한 건뿐이면 "한 건만 바뀌는지"를 알 수 없다. 메모 두 건을 만든 뒤 한 건만 고친다.

**[dev]**

```bash
curl -s -X POST http://app:8000/memos -H "Content-Type: application/json" -d '{"title": "장보기", "content": "우유"}'
curl -s -X POST http://app:8000/memos -H "Content-Type: application/json" -d '{"title": "운동", "content": "달리기"}'
curl -s http://app:8000/memos
```

목록에서 방금 만든 두 메모의 번호를 확인한다. 아래 명령에서 **A** 는 "장보기" 메모의 번호, **B** 는 "운동" 메모의 번호로 바꿔 친다. (예: A 는 3, B 는 4)

**[dev]**

```bash
curl -s -X PUT http://app:8000/memos/A -H "Content-Type: application/json" -d '{"title": "장보기(수정)", "content": "우유, 두부"}'
curl -s http://app:8000/memos
```

- [ ] A 번 메모만 `장보기(수정)` 으로 바뀌었다.
- [ ] **B 번 메모(`운동`)는 그대로다.** 다른 메모가 함께 바뀌지 않았다.

지우기도 같은 방식으로 본다.

**[dev]**

```bash
curl -s -o /dev/null -w "%{http_code}\n" -X DELETE http://app:8000/memos/B
curl -s http://app:8000/memos
```

- [ ] 상태 코드가 `204` 다.
- [ ] 목록에 A 번 메모가 **남아 있다.** 지우라고 한 B 번만 사라졌다.

**(4) 없는 번호와 규칙 위반**

**[dev]**

```bash
curl -s -X DELETE http://app:8000/memos/B
curl -s -X PUT http://app:8000/memos/999 -H "Content-Type: application/json" -d '{"title": "없는 메모", "content": ""}'
curl -s -o /dev/null -w "%{http_code}\n" -X PUT http://app:8000/memos/A -H "Content-Type: application/json" -d '{"title": "", "content": ""}'
```

- [ ] 이미 지운 B 번을 다시 지우면 `{"detail":"메모를 찾을 수 없습니다."}` 가 나온다.
- [ ] 없는 번호 999 를 고치면 같은 문구가 나온다.
- [ ] 빈 제목으로 고치면 마지막 줄이 `422` 다. 고치기에도 입력 규칙이 적용된다.

**(5) 요구사항 대조**

1단계에서 적은 R4, R5 조건을 하나씩 짚는다. 각 조건을 확인한 방법(위의 명령 중 어느 것)을 옆에 적는다. 확인하지 못한 조건이 있으면 AI 에게 테스트를 추가하게 한다.

### 5단계. 코드 대신 설명 듣기 (15분)

코드를 읽을 필요는 없다. 아래 질문을 AI 에게 하고, 답을 **4단계의 결과와 맞춰 본다.**

**[AI]**

```text
파일은 고치지 말고 설명만 해 줘. 메모를 고치는 요청(PUT)이 들어와 200 이 나갈 때까지 어떤 일이 어떤 순서로 일어나는지 번호를 붙여 알려 줘.
```

```text
파일은 고치지 말고 설명만 해 줘. 없는 번호를 고치거나 지우려 할 때 404 는 어디에서 만들어지는가?
```

```text
tests/test_memos.py 에 "메모 두 건 중 한 건만 고쳐졌을 때 다른 한 건은 바뀌지 않는다"를 확인하는 테스트가 있어? 있으면 이름을, 없으면 없다고 말해 줘.
```

**테스트가 못 잡는 것을 확인하기.** 마지막 질문의 답이 "없다"였다면, 테스트에 빈틈이 있는 것이다. 아래처럼 요청한다.

**[AI]**

```text
메모 두 건을 만든 뒤 한 건만 고쳤을 때 다른 한 건은 바뀌지 않는다는 것을 확인하는 테스트를 tests/test_memos.py 에 추가해 줘. 삭제에 대해서도 같은 테스트를 추가해 줘. 기존 테스트는 건드리지 마. 먼저 계획을 말해 줘.
```

추가가 끝나면 `sh scripts/verify.sh` 로 통과를 확인한다. 4단계 (3)에서 한 손 시험을 테스트가 대신하게 된 것이다.

> 방금 한 일에 이름이 있다. **테스트가 실제로 지켜 주는지 직접 확인하는 것.** 테스트를 믿어도 되는지 확인하는 가장 확실한 방법이다.

### 6단계. CRUD 한 장으로 정리하기 (10분)

완성된 CRUD 를 표로 정리한다. 4단계에서 직접 해 본 결과를 채운다.

| 하는 일 | HTTP | 성공 | 실패 |
|---|---|---|---|
| 만들기 | `POST /memos` | 201 | 422 |
| 목록 | `GET /memos` | 200 | — |
| 한 건 | `GET /memos/{id}` | 200 | 404 |
| 고치기 | `PUT /memos/{id}` | 200 | 404, 422 |
| 지우기 | `DELETE /memos/{id}` | 204 | 404 |

이 표를 `harness/WORKLOG.md` 의 9교시 기록에 붙인다. 12교시 발표에 쓴다.

## 하네스 관점 — 이번 교시에서 본 것

- **테스트 조건의 세 가지 모양.** 6교시 "만들어라", 8교시 "한 글자도 바꾸지 마라", 9교시 "늘리기만 해라". 작업의 성격에 따라 테스트를 묶는 방식이 달라진다. 매번 `git diff` 한 줄로 확인했다.
- **위험한 작업일수록 사람이 직접 본다.** 되돌릴 수 없는 고치기·지우기는 메모 두 건으로 실제 결과를 확인했다.
- **테스트도 검증 대상이다.** 테스트가 빈틈을 놓쳤다면, 그 빈틈을 메우는 것이 하네스를 고치는 일이다.
- **지시서를 쓰는 것이 설계다.** 2단계에서 범위와 "하지 말 것"을 정할 때, 이미 무엇을 어떻게 만들지 절반은 결정했다.

## 자주 만나는 오류

| 증상 | 원인과 해결 |
|---|---|
| PUT 이 405 `Method Not Allowed` | 고치기 기능이 없거나 주소가 다르다. `/docs` 에서 PUT 이 보이는지 확인한다. |
| PUT 에 제목만 보냈더니 내용이 지워졌다 | 정상이다. PUT 은 전체를 바꾼다. 안 보낸 `content` 는 빈 글자가 된다. |
| 고쳤는데 다른 메모까지 바뀌었다 | AI 가 한 건만 고르는 조건을 빠뜨렸다. 4단계 (3)의 결과를 AI 에게 붙여 주고 고치게 한다. 바뀐 내용은 되돌릴 수 없으니 메모를 다시 만든다. |
| DELETE 가 200 과 `null` 을 돌려준다 | 성공 코드를 204 로 해야 한다. 요구사항 R5 를 가리켜 고치게 한다. |
| `git diff tests/` 의 `-` 줄에 출력이 있다 | 기존 테스트의 줄이 지워졌거나 바뀌었다. 전체를 읽고, 이유를 AI 에게 묻는다. |

## 확인 문제

1. PUT 과 DELETE 의 성공 상태 코드가 다른 이유를 설명하시오.
2. 고치기 요청에서 번호는 주소에서, 내용은 본문에서 온다. 이 둘을 요청 모양으로 그려 보시오.
3. 고치기에도 만들기와 같은 입력 규칙(빈 제목 → 422)이 적용되는 이유를 요구사항 R6 에서 찾아 쓰시오.
4. 메모가 한 건뿐인 상태에서 시험하면 "다른 메모가 바뀌었는지"를 알 수 없는 이유는 무엇인가?
5. 8교시와 9교시의 테스트 파일 조건은 어떻게 다른가? 각각 어떤 명령으로 확인했는가?
6. 내가 쓴 지시서와 준비된 지시서를 비교했을 때, 내 것에 빠져 있던 조건 하나와 그것이 없으면 생길 수 있는 일을 쓰시오.
