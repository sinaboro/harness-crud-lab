# 4교시. CRUD 와 HTTP 기초

| | |
|---|---|
| 시간 | 2시간 |
| 실습 결과 | 메모를 만들고(POST) 보는(GET) 주소를 직접 시험한다 |
| 시작 상태 | 3교시를 마친 상태 (`/hello` 가 동작하고 커밋되어 있다) |

> 이 교시에서는 코드를 **직접 쓰지 않는다.** 메모를 만들고 보는 주소가 이미 들어 있는 완성 예시를 가져와서, 그것이 어떻게 동작하는지 시험한다.

## 수업의 흐름에서 이번 교시의 위치

```text
 ① 요구사항 작성 → ② AI 에게 지시 → ③ 하네스로 제어 → ④ 실행·테스트 → ⑤ 수정·재검증·저장
 └─ 이번 교시: 요구사항에 쓰이는 "말"(주소·방식·상태 코드·JSON)을 배운다
```

`harness/REQUIREMENTS.md` 는 "`POST /memos` 를 부르면 201 을 돌려준다"처럼 적혀 있다. 이 문장을 읽을 수 있어야 AI 에게 정확히 시킬 수 있고, AI 의 결과가 맞는지 판단할 수 있다.

## 학습 목표

1. CRUD 네 가지를 HTTP 방식(POST·GET·PUT·DELETE)과 짝지을 수 있다.
2. 요청과 응답이 무엇으로 이루어지는지 말할 수 있다.
3. 상태 코드 200·201·204·404·422 의 뜻을 안다.
4. `/docs` 와 `curl` 로 메모를 만들고 보는 주소를 시험한다.
5. 메모리에 저장한 데이터가 서버를 다시 켜면 사라지는 것을 확인한다.

## 1. 개념

### CRUD

데이터를 다루는 일은 결국 네 가지다.

| | 뜻 | 메모장에서 |
|---|---|---|
| **C**reate | 만들기 | 새 메모 쓰기 |
| **R**ead | 읽기 | 메모 목록 보기, 메모 한 건 보기 |
| **U**pdate | 고치기 | 메모 내용 바꾸기 |
| **D**elete | 지우기 | 메모 지우기 |

### HTTP — 브라우저와 서버가 주고받는 말

브라우저(클라이언트)가 **요청**을 보내고 서버가 **응답**을 돌려준다. 한 번 묻고 한 번 답하면 끝이다.

**요청**은 세 부분이다.

| 부분 | 뜻 | 예 |
|---|---|---|
| 방식 | 무엇을 하려는가 | `GET`, `POST`, `PUT`, `DELETE` |
| 주소 | 무엇에 대해서인가 | `/memos`, `/memos/1` |
| 본문 | 함께 보내는 데이터 (없을 수도 있다) | `{"title": "장보기"}` |

**응답**은 두 부분이다.

| 부분 | 뜻 | 예 |
|---|---|---|
| 상태 코드 | 어떻게 되었는가 (세 자리 숫자) | `200`, `404` |
| 본문 | 돌려주는 데이터 (없을 수도 있다) | `{"id": 1, "title": "장보기"}` |

### CRUD ↔ HTTP

같은 일을 두 가지 말로 부른다. 이 표는 과정 내내 쓴다.

| 하는 일 | HTTP 방식 + 주소 | 성공 상태 코드 |
|---|---|---|
| 만들기 | `POST /memos` | 201 |
| 목록 보기 | `GET /memos` | 200 |
| 한 건 보기 | `GET /memos/1` | 200 |
| 고치기 | `PUT /memos/1` | 200 |
| 지우기 | `DELETE /memos/1` | 204 |

주소가 `/memos` 하나인데 방식에 따라 하는 일이 달라진다. 주소는 **무엇**(메모들)을 가리키고, 방식은 **어떻게**(만든다/본다)를 말한다.

### 상태 코드

| 코드 | 이름 | 뜻 | 메모장에서 |
|---|---|---|---|
| 200 | OK | 성공 | 목록 보기, 고치기 성공 |
| 201 | Created | 성공했고 새로 만들어졌다 | 메모 만들기 성공 |
| 204 | No Content | 성공했고 돌려줄 내용이 없다 | 메모 지우기 성공 |
| 404 | Not Found | 그런 것이 없다 | 없는 번호의 메모를 찾을 때 |
| 422 | Unprocessable Content | 보낸 데이터가 규칙에 맞지 않는다 | 제목 없이 만들려 할 때 |
| 500 | Internal Server Error | 서버 코드가 오류를 냈다 | 서버 쪽 버그 |

첫 자리로 큰 뜻을 안다. **2xx 는 성공, 4xx 는 요청한 쪽의 잘못, 5xx 는 서버의 잘못.**

### JSON

요청과 응답의 본문은 **JSON** 이라는 형식으로 쓴다. 이름과 글자는 **큰따옴표**로 감싼다.

```json
{"id": 1, "title": "장보기", "content": "우유, 달걀"}
```

메모 여러 건은 대괄호로 감싼다: `[ {…}, {…} ]`

## 따라 하기

### 1단계. 4교시 완성 예시 가져오기 (5분)

**[dev]**

```bash
sh scripts/checkpoint.sh 04
```

```text
checkpoints/lesson04 의 app, tests 를 가져왔습니다.
```

이제 메모를 만들고 보는 주소(`/memos`)가 들어 있다. 코드를 읽을 필요는 없다. 아래에서 **무엇을 하는지**만 확인한다.

### 2단계. `/docs` 에서 시험하기 (15분)

브라우저에서 http://localhost:8000/docs 를 새로 고친다. `POST /memos` 와 `GET /memos` 가 보이면 된다.

**(1) 목록 보기.** `GET /memos` → **Try it out** → **Execute**.

- Code: `200`
- Response body: `[]` (아직 메모가 없다)

**(2) 만들기.** `POST /memos` → **Try it out**. Request body 칸을 아래 내용으로 바꾸고 **Execute**.

```json
{"title": "장보기", "content": "우유, 달걀"}
```

- Code: `201`
- Response body: `{"id":1,"title":"장보기","content":"우유, 달걀"}`

**(3) 내용 없이 하나 더.**

```json
{"title": "운동"}
```

- Response body: `{"id":2,"title":"운동","content":""}` — `content` 는 안 보냈지만 빈 글자로 채워졌다.

**(4) 다시 목록 보기.** `GET /memos` → **Execute**. 두 메모가 대괄호 안에 들어 있다.

### 3단계. `curl` 로 시험하기 (20분)

`/docs` 는 마우스로 눌러야 한다. 같은 일을 명령 한 줄로 하는 도구가 `curl` 이다. AI 에이전트도 서버를 확인할 때 `curl` 을 쓴다.

**[dev]** 에서 실행한다. 주소가 `localhost` 가 아니라 **`app`** 이라는 점에 주의한다. 컨테이너끼리는 서비스 이름으로 서로를 부른다.

**[dev]**

```bash
curl -s http://app:8000/memos
```

**만들기.** 아래 명령을 그대로 친다. 옵션의 뜻은 표로 적어 두었다.

**[dev]**

```bash
curl -s -X POST http://app:8000/memos -H "Content-Type: application/json" -d '{"title": "책 읽기", "content": "30쪽"}'
```

| 옵션 | 뜻 |
|---|---|
| `-s` | 진행 표시를 숨긴다 |
| `-X POST` | 방식을 POST 로 한다 (안 쓰면 GET) |
| `-H "Content-Type: application/json"` | "본문은 JSON 입니다"라고 알린다 |
| `-d '…'` | 본문. 바깥은 작은따옴표, 안의 JSON 은 큰따옴표 |

**상태 코드만 보기.**

**[dev]**

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://app:8000/memos
```

```text
200
```

**규칙에 맞지 않는 요청 보내기.** 제목 없이 내용만 보낸다.

**[dev]**

```bash
curl -s -X POST http://app:8000/memos -H "Content-Type: application/json" -d '{"content": "제목이 없어요"}'
```

```text
{"detail":[{"type":"missing","loc":["body","title"],"msg":"Field required","input":{"content":"제목이 없어요"}}]}
```

읽는 법:

- `"msg":"Field required"` — 꼭 있어야 하는 칸(`title`)이 빠졌다.
- `"loc":["body","title"]` — 본문(`body`)의 `title` 칸에서 문제가 생겼다.

상태 코드도 확인한다.

**[dev]**

```bash
curl -s -o /dev/null -w "%{http_code}\n" -X POST http://app:8000/memos -H "Content-Type: application/json" -d '{"content": "제목이 없어요"}'
```

```text
422
```

### 4단계. 요구사항과 한 줄씩 대조하기 (15분)

`harness/REQUIREMENTS.md` 의 R1, R2, R6 을 읽는다. 아래 표의 "확인 방법"대로 직접 확인하고, 결과 칸에 **맞다** 또는 **아니다** 를 적는다.

| 요구사항 | 확인 방법 | 결과 (맞다 / 아니다) |
|---|---|---|
| R1. 만들면 201 | 2단계 (2)의 POST 결과 | |
| R1. 응답에 `created_at`, `updated_at` 이 있다 | 2단계 (2)의 응답 내용을 본다 | |
| R1. `content` 를 빼면 `""` 로 저장된다 | 2단계 (3)의 응답을 본다 | |
| R2. 목록은 200 과 배열이다 | 2단계 (4)의 결과 | |
| R2. **나중에 만든 메모가 앞에** 온다 | 목록에서 `id` 1 과 2 중 어느 것이 앞에 있는지 본다 | |
| R6. `title` 이 없으면 422 | 3단계의 422 결과 | |
| R6. `title` 이 **빈 글자**(`""`)이면 422 | 아래 명령을 치고 상태 코드를 본다 | |

**[dev]**

```bash
curl -s -o /dev/null -w "%{http_code}\n" -X POST http://app:8000/memos -H "Content-Type: application/json" -d '{"title": ""}'
```

결과를 다 적었으면 **요구사항을 지키지 못한 항목이 몇 개인가?** 세어 본다.

> 이것이 "돌아가는 것 같다"와 "요구사항을 만족한다"의 차이다. 화면에서 눌러 보면 잘 되는 것처럼 보여도, 요구사항 문장과 한 줄씩 대조하면 빠진 것이 드러난다. 6교시에 AI 가 이 빠진 부분을 채운다.

## 하네스 관점 — 이번 교시에서 본 것

- 요구사항은 **HTTP 의 말**로 쓴다. "`POST /memos` → 201". 이 말을 알아야 요구사항을 쓸 수 있고, AI 의 결과를 판단할 수 있다.
- 4단계의 대조표는 사람이 하면 느리고 빠뜨리기 쉽다. 이 대조를 **테스트**로 적어 두면 매번 자동으로 확인된다. 6교시에 AI 가 요구사항마다 테스트를 만든다.

## 자주 만나는 오류

| 증상 | 원인과 해결 |
|---|---|
| `curl: (6) Could not resolve host: app` | 윈도우 PowerShell 에서 쳤다. `app` 이라는 이름은 컨테이너 안에서만 통한다. dev 컨테이너에서 친다. |
| `curl: (7) Failed to connect to app port 8000` | 서버가 꺼져 있다. **[PS]** `docker compose logs app --tail 20` 을 읽는다. |
| `{"detail":"Method Not Allowed"}` (405) | 주소는 있는데 그 방식의 기능이 없다. `-X POST` 를 빠뜨렸는지 본다. |
| `{"detail":[{"type":"json_invalid", …` | 본문이 올바른 JSON 이 아니다. 작은따옴표를 썼거나, 쉼표·중괄호가 빠졌다. |
| PowerShell 에서 `curl … -d '{"title": …}'` 이 422 | PowerShell 은 따옴표를 다르게 처리한다. 본문이 있는 `curl` 은 dev 컨테이너에서 친다. |
| 방금 만든 메모가 없어졌다 | 파일을 저장해서 서버가 다시 켜졌다. 5단계에서 본 현상이다. 정상이다. |

## 확인 문제

1. CRUD 네 가지를 HTTP 방식·주소와 짝지어 표로 쓰시오.
2. `GET /memos` 와 `POST /memos` 는 주소가 같다. 서버는 둘을 어떻게 구분하는가?
3. 상태 코드 201 과 204 는 둘 다 성공이다. 무엇이 다른가?
4. 없는 번호의 메모를 조회하면 어떤 상태 코드가 와야 하는가? 왜 200 과 빈 내용을 돌려주면 안 되는가?
5. `{'title': '장보기'}` 는 올바른 JSON 인가? 아니라면 어디가 틀렸는가?
6. 제목은 **반드시** 보내야 하고 내용은 안 보내도 된다. 이 차이를 요구사항 R1 과 R6 에서 찾아 설명하시오.
7. 9교시에 "지우기"가 생기면, 지금의 번호 정하는 방식(목록 개수로 정한다)에 어떤 문제가 생기는가?
8. 서버를 다시 켰을 때 메모가 사라진 이유를 설명하시오.
