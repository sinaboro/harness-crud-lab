# 작업 기록

> 교시마다 **내가 시킨 일**과 **내가 이해한 것**을 적는다.
> AI 가 만든 코드를 "내 코드"로 만드는 과정이다. 설명하지 못하는 코드는 커밋하지 않는다.
> 12교시 발표는 이 기록을 바탕으로 한다.

---

## 적는 방법

교시가 끝날 때마다 아래 틀을 복사해서 채운다.

```markdown
## N교시 — (작업 이름)

- 날짜:
- 작업 지시서: harness/tasks/…
- 커밋: (git log --oneline -1 의 결과)

### 1. AI 에게 시킨 일 (한 문장)

### 2. AI 가 세운 계획 중 내가 고치게 한 것
(없으면 "없음". 있으면 무엇을 왜 고치게 했는지)

### 3. 하네스가 막거나 물어본 것
(권한 때문에 막힌 명령, 물어봐서 내가 허락/거절한 것, 검증이 실패한 횟수)

### 4. 바뀐 코드를 내 말로 설명하기 (세 문장)
1.
2.
3.

### 5. 새로 알게 된 것
(용어, 문법, 명령)

### 6. 아직 이해하지 못한 것
(AI 에게 물어볼 질문으로 적는다)
```

## 작성 예시

## 6교시 — 메모 만들기·보기 초안

- 날짜: (작성)
- 작업 지시서: harness/tasks/06_memo_draft.md
- 커밋: (작성)

### 1. AI 에게 시킨 일 (한 문장)

메모를 만들고(POST), 목록과 한 건을 보는(GET) API 를 메모리 저장소로 만들게 했다.

### 2. AI 가 세운 계획 중 내가 고치게 한 것

계획에 "삭제 API 도 함께 만든다"가 있어서, 지시서 4번(하지 말 것)을 가리키며 빼게 했다.

### 3. 하네스가 막거나 물어본 것

- `pip install` 을 실행하려고 해서 물어봤다 → 거절했다. (새 패키지는 쓰지 않기로 했다)
- 검증 1회 실패(안 쓰는 import) → AI 가 스스로 고치고 다시 실행해서 통과.

### 4. 바뀐 코드를 내 말로 설명하기 (세 문장)

1. `schemas.py` 의 `MemoIn` 이 요청의 모양을 정하고, 제목이 비었거나 100자를 넘으면 FastAPI 가 422 를 돌려준다.
2. 메모는 `{번호: 메모}` 딕셔너리에 넣고, 번호는 `next_id` 로 따로 세어서 겹치지 않게 한다.
3. 없는 번호를 조회하면 `HTTPException(404)` 를 일으켜서 정해진 오류 문구를 돌려준다.

### 5. 새로 알게 된 것

- `response_model`: 응답의 모양을 정해 두면 그 모양대로만 나간다.
- `raise`: 함수를 그 자리에서 끝내고 오류를 알린다.

### 6. 아직 이해하지 못한 것

- `global next_id` 는 왜 필요한가? 없으면 어떤 오류가 나는가?
