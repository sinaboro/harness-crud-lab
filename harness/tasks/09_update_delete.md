# 작업 지시서: 메모 고치기·지우기 (9교시)

## 1. 목표
메모를 고치는 API 와 지우는 API 를 더해서 CRUD 네 가지를 완성한다.

## 2. 요구사항
`harness/REQUIREMENTS.md` 의 **R4, R5** 를 구현한다. 고치기에는 **R6**(입력 규칙)이 똑같이 적용된다.

## 3. 범위
- 고쳐도 되는 파일: `app/main.py`, `tests/test_memos.py`(테스트 **추가**만)
- 고치면 안 되는 것: 이미 있는 테스트의 내용, `app/db.py` 의 테이블 구조

## 4. 하지 말 것
- "일부만 고치기"(PATCH)는 만들지 않는다. 고치기는 PUT 하나로, 제목과 내용을 모두 받는다.
- 지운 메모를 되살리는 기능(휴지통)을 만들지 않는다.
- 화면(HTML)을 만들지 않는다. (10교시에 한다)

## 5. 구현 조건
- 고칠 때 `updated_at` 을 현재 시각으로 바꾼다. `created_at` 은 바꾸지 않는다.
- `UPDATE` 와 `DELETE` 에는 반드시 `WHERE id = %s` 를 쓴다.
- 없는 번호를 고치거나 지우려 하면 404 와 `{"detail": "메모를 찾을 수 없습니다."}` 를 돌려준다. (R3 과 같은 문구)
- 404 를 만드는 코드가 여러 곳에 반복되면 한 곳으로 모은다.

## 6. 완료 조건
- [ ] `sh scripts/verify.sh` 가 "검증 통과"로 끝난다. 테스트 개수가 작업 전보다 **늘었다.**
- [ ] R4 테스트: 고치기 성공, 고친 뒤 다시 조회해도 바뀐 내용이 남아 있음, 없는 번호는 404, 빈 제목은 422
- [ ] R5 테스트: 지우기 성공(204), 지운 뒤 조회하면 404, 없는 번호는 404
- [ ] `git diff tests/` 에서 **지워진 줄(-)이 없다.** (기존 테스트를 건드리지 않았다)

## 7. 진행 방법
`AGENTS.md` 의 작업 절차를 따른다. 먼저 계획을 말하고, 내가 "진행"이라고 하면 구현한다.
끝나면 `AGENTS.md` 의 보고 형식으로 보고한다.
