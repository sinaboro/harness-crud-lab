# 요구사항 명세 — 메모 CRUD

> 수업 흐름의 **① 사람이 요구사항 작성**에 해당하는 문서다.
> "무엇을 만들 것인가"를 사람이 정해서 적는다. "어떻게 만들 것인가"는 적지 않는다.
> AI 에이전트는 이 문서를 기준으로 구현하고, 테스트는 이 문서의 번호(R1 ...)를 하나씩 확인한다.

---

## 1. 한 문장 요약

브라우저에서 메모를 쓰고, 목록으로 보고, 고치고, 지울 수 있는 메모장. 메모는 PostgreSQL 에 저장되어 서버를 껐다 켜도 남아 있다.

## 2. 메모 한 건의 모양

| 항목 | 타입 | 설명 |
|---|---|---|
| `id` | 정수 | 서버가 자동으로 붙이는 번호 (1, 2, 3 ...). 사용자가 정하지 않는다. |
| `title` | 문자열 | 제목. 필수. 1~100자. |
| `content` | 문자열 | 내용. 선택. 최대 1000자. 안 보내면 빈 문자열(`""`). |
| `created_at` | 날짜·시각 | 만든 시각. 서버가 기록한다. |
| `updated_at` | 날짜·시각 | 마지막으로 고친 시각. 서버가 기록한다. |

## 3. 기능 요구사항

각 요구사항은 **부르는 방법 → 기대하는 결과**로 적는다. 이 형식 그대로 테스트가 된다.

### R1. 메모 만들기 (Create)

- `POST /memos` 에 `{"title": "장보기", "content": "우유, 달걀"}` 을 보내면
- 상태 코드 **201** 과 함께, 만들어진 메모(id, title, content, created_at, updated_at)를 돌려준다.
- `content` 를 빼고 보내면 `content` 는 `""` 로 저장된다.

### R2. 메모 목록 보기 (Read)

- `GET /memos` 를 부르면 상태 코드 **200** 과 메모 목록(배열)을 돌려준다.
- **나중에 만든 메모가 앞에** 온다 (id 내림차순).
- 메모가 하나도 없으면 빈 배열 `[]` 을 돌려준다.

### R3. 메모 한 건 보기 (Read)

- `GET /memos/1` 을 부르면 상태 코드 **200** 과 1번 메모를 돌려준다.
- 그 번호의 메모가 없으면 상태 코드 **404** 와 `{"detail": "메모를 찾을 수 없습니다."}` 를 돌려준다.

### R4. 메모 고치기 (Update)

- `PUT /memos/1` 에 `{"title": "새 제목", "content": "새 내용"}` 을 보내면
- 상태 코드 **200** 과 함께 고쳐진 메모를 돌려준다. `updated_at` 은 고친 시각으로 바뀐다.
- 다시 조회해도 고친 내용이 남아 있다.
- 그 번호의 메모가 없으면 **404** (문구는 R3 과 같다).

### R5. 메모 지우기 (Delete)

- `DELETE /memos/1` 을 부르면 상태 코드 **204** 를 돌려준다. 응답 내용은 없다.
- 지운 뒤 `GET /memos/1` 을 부르면 **404** 가 온다.
- 그 번호의 메모가 없으면 **404** (문구는 R3 과 같다).

### R6. 입력 규칙

만들기(R1)와 고치기(R4)에 똑같이 적용한다. 규칙을 어기면 상태 코드 **422** 를 돌려주고 저장하지 않는다.

- `title` 이 없거나 빈 문자열(`""`)이면 422
- `title` 이 100자를 넘으면 422
- `content` 가 1000자를 넘으면 422
- `title` 이 공백뿐(`"   "`)이면 422 — *11교시에 추가*
- `title` 의 앞뒤 공백은 잘라 내고 저장한다 (`"  장보기  "` → `"장보기"`) — *11교시에 추가*

### R7. 웹 화면

- 브라우저로 `GET /` 에 들어가면 "메모장" 화면(HTML)이 나온다.
- 화면에서 메모를 **쓰고, 목록으로 보고, 고치고, 지울 수** 있다. 화면은 R1~R5 의 API 를 불러서 동작한다.
- 저장·수정·삭제 뒤에는 새로 고침 없이 목록이 바뀐다.
- 입력이 규칙에 맞지 않으면 화면에 안내 문구가 나온다.

### 그 밖의 주소

- `GET /health` → **200**, `{"status": "ok"}` (서버가 살아 있는지 확인)
- `GET /hello` → **200**, `{"message": "안녕하세요, 하네스!"}`
- `GET /hello?name=철수` → **200**, `{"message": "안녕하세요, 철수!"}`

## 4. 품질 요구사항

기능이 아니라 "어떤 식으로 만들어져야 하는가"에 대한 약속이다.

| 번호 | 내용 |
|---|---|
| N1 | 메모는 PostgreSQL 에 저장한다. 서버를 다시 켜도 메모가 남아 있다. *(8교시부터)* |
| N2 | SQL 에 값을 넣을 때 자리표시자(`%s`)를 쓴다. 문자열을 이어 붙이지 않는다. |
| N3 | 모든 소스 파일에 한국어 주석(파일 머리 설명 + 핵심 줄 설명)이 있다. |
| N4 | API 키와 비밀번호는 코드에 적지 않는다. 환경 변수에서 읽는다. |
| N5 | 모든 기능 요구사항에 자동 테스트가 있고, `sh scripts/verify.sh` 가 통과한다. |
| N6 | 화면은 프레임워크 없이 HTML·CSS·자바스크립트만으로 만든다. 사용자가 쓴 글은 `textContent` 로 넣는다. |

## 5. 이번에는 만들지 않는 것

범위를 정해 두지 않으면 AI 는 시키지 않은 기능까지 만든다. 아래는 **만들지 않는다.**

- 로그인, 회원 가입, 사용자별 메모
- 검색, 태그, 정렬 바꾸기, 페이지 나누기
- 파일 첨부, 이미지
- 화면 꾸미기 프레임워크(React, Bootstrap 등)

## 6. 교시별 구현 범위

| 교시 | 구현하는 요구사항 | 저장소 |
|---|---|---|
| 3 | `/health`, `/hello` | — |
| 6 | R1, R2, R3, R6(공백 규칙 제외) | 메모리(딕셔너리) |
| 8 | R1, R2, R3, R6 그대로 + N1 | PostgreSQL |
| 9 | R4, R5 | PostgreSQL |
| 10 | R7 | PostgreSQL |
| 11 | R6 의 공백 규칙 두 가지 | PostgreSQL |
